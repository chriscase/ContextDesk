## Acceptance criteria

1. TID-1 Workflow. On War Room, Investigation First, Keystone, and Beacon, an operator can filter by software-impact identity, contributor, and recorded-at range beside the existing search, status, entity, and archive controls; inspect the returned rows; reload a canonical shell URL that restores those same filters and results; switch presentation and continue through later pages; and open the investigation identified by the chosen row. The URL round-trips only the shareable query. It never contains an opaque cursor, page size, or collection schema id.
2. TID-2 Server semantics. Filters use the server's existing rules, unchanged: recorded-at compares case `createdAt` (not observed occurrence); contributor matches participant identity; impact identity uses the existing normalized identity key; rows are newest `createdAt` then ascending id; facet counts and `otherCount` are the server's authorized-collection counts, not a client recount of the filtered page; hidden-archive count and next cursor stay server-owned. The page-local War Room "Observed from" control stays a loaded-page observed-date filter and is not relabeled as recorded-at.
3. TID-3 Honest scope. Empty, filtered-empty, loading, error, failed-refresh/stale, and denied states stay distinct in every presentation. A contributor-only or recorded-date-only filter that matches nothing, including the existing War Room omission, must not say that no investigations have been recorded. Changing query, identity, or authority drops prior rows, facets, and cursors and does not apply a stale callback under the new scope. A denied reader issues zero collection requests.
4. TID-4 Pages. Continuation keeps server order, deduplicates by stable first occurrence, and keeps the newest server facets, hidden-archive count, and cursor. Explicit retry repeats the current scope. A stale or rejected cursor restarts that scope from the beginning instead of appending old pages. Cursors stay out of shell URLs.
5. TID-5 Proof and publication. Before any implementation commit, freeze the full Goal 1 text with stable acceptance IDs and a content hash. Prove the journey with real synthetic browser runs through every presentation, deterministic negative tests, and mutation sensitivity that makes each load-bearing guarantee fail when inverted and pass again when restored. Also exercise at least one disposable production-server path (built production server entry and disposable data, not the memory browser fixture and not shared production data).
